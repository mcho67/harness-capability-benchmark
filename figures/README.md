# Figures

Every figure in the paper is generated by a script in `scripts/`, and every
script writes both a **PNG** (300 dpi, for drafts and for pasting into Google
Docs) and a **PDF** (vector, for the final typeset paper). Nothing is drawn by
hand and nothing is edited after export — if a figure is wrong, the script is
wrong, and re-running it is the fix.

Run one:

```
python docs/figures/scripts/fig01_request_path.py
```

## Conventions

These hold for every figure, so the set reads as one system.

- **Grayscale-safe.** The paper may be printed or read in black and white.
  No figure may depend on hue alone to carry meaning.
- **Cell ids are fixed** and match the analysis code everywhere:
  **C1** deciding × cloud, **C2** deciding × on-device,
  **C3** routing × cloud, **C4** routing × on-device.
- **Numbers carry n.** Any figure showing a rate shows the sample size it
  came from, in the figure or in its caption.
- **Design figures carry no results.** Figures 1–14 describe how the study was
  built and must contain no outcome number, so a reader meets the design
  before meeting the finding.
- **One accent** (`#33506A`) for structural chrome; ink `#1B1B1B`, muted
  `#6B6B6B`, rules `#C9C6C0`, surfaces `#F5F4F1`.
- Type is left at the matplotlib default sans (DejaVu) so the figures render
  identically on any machine.

**Figure 10 and the action-matching rule.** The action row is recomputed under
the any-of reading — the rater agrees when an action they named is one the
ideal accepts. That is the standard `score.py:_tools_ok` applies to the
assistant (`bool(set(ideal_tools) & used_set)`), so grading the rater by exact
string would hold the rater stricter than the thing being graded. The figure
derives the number from `ideal_agreement.json`'s own disagreement list rather
than transcribing it, and that file's stored `action_choice` (0.558) is the
whole-cell reading, which its own note does not describe. Appendix C should
report all three readings so a reader who recomputes and gets 0.302 can see
nothing was hidden.


## ⚠ Figure 16 — the sign

**Compensation means the two lines DIVERGE going from cloud to on-device.**

If the deciding design were compensating for the weaker model, it would lose
*less* on the way down, so the vertical gap between the lines would **widen**
on the on-device side. Converging lines mean **negative** compensation.

Check against the real cell means before drawing anything:

| | cloud | on-device | gap |
|---|---|---|---|
| deciding | 0.838 | 0.521 | — |
| routing | 0.658 | 0.388 | — |
| **gap between designs** | **0.179** | **0.133** | narrows |

The gap narrows, so compensation is negative (−0.046). The lines in Figure 16
converge slightly, and Figure 3 marks that shape as the observed one.

This direction has been written backwards once already, in an earlier draft of
`how_the_study_was_built.md` (see its Stage 3.5, which now carries a worked
example). Verify every sign statement against the four numbers above rather
than against intuition.

## Where the numbers come from

Every result figure imports `scripts/_data.py`, which reads
`runs/full-2026-08-20/scored.jsonl` directly. No number is transcribed by hand
between the run and the page, so a figure cannot drift out of step with the
record.

`_data.bootstrap` is the same procedure the analysis used, down to the
generator: `numpy.random.default_rng(20260819)` with `numpy.percentile`, drawing
48 tasks with replacement and carrying each drawn task's five repetitions with
it, 5,000 times. It reproduces the frozen record exactly — the compensation
contrast comes back as −0.045833 [−0.195833, +0.100000], matching
`report.json` to six decimals.

**Check the interval, not just the point.** This file once used Python's
`random.Random` with the same seed, which is a different generator and so a
different set of resamples. The point estimate was unaffected and the figure
looked right, but every interval it drew was slightly wrong — the headline
printed [−0.200, +0.108] against the record's [−0.196, +0.100]. A seed matching
is not the same as a generator matching.

The flat forms of the same record, for reading rather than plotting, are
`docs/results.md` and `runs/full-2026-08-20/runs.csv`, both written by
`tools/export_results.py`.
